# SEO delivery knowledge

Use this when an Upwork job includes SEO, local SEO, a website audit, keyword research, content architecture or organic growth. It is a compact implementation map distilled from the Jono SEO Blueprint. It belongs to this repository so the Upwork OS works on another member's machine without Jono installed.

## The SEO delivery flow

Use this order. It is the big picture behind the individual checks and tools.

1. **Protect the baseline:** confirm the offer, buyer, service area and exclusions. Inventory every current URL, ranking page, conversion path and relevant account before anything moves.
2. **Map real demand:** combine Search Console with keyword research, verify the live search intent, then assign one primary intent to each page. The result is a shallow hub-and-spoke sitemap plus a redirect map for every old URL.
3. **Build the conversion path:** create the approved page types in hierarchy order, hubs before spokes. Write service pages before profile or directory work needs somewhere to link. Use verified proof beside the claim it supports.
4. **Make the build search-ready:** add titles, descriptions, headings, schema, image text, internal links, canonicals and crawlable HTML. Preserve privacy requirements and prove the important conversion path works.
5. **Launch without losing value:** test the rendered site, speed, forms, sitemap, robots and indexability. Publish, apply every redirect, connect Search Console and request indexing for the priority pages.
6. **Learn and expand:** compare searches, qualified enquiries and local visibility with the frozen baseline. Improve the page map, content, Google Business Profile, reviews and internal links from measured gaps.

The build can stop after stage 5 when the job is a finite website launch. Stage 6 becomes the ongoing SEO lane only when it is in scope.

## Job-specific lanes

- **Audit:** inventory, baseline, competitor benchmark, technical and on-page findings, impact order, then an approval gate before fixes.
- **Keyword strategy:** market and service confirmation, wide pull, live intent checks, realistic difficulty, clustering, cannibalization gate and a prioritized page map.
- **Local SEO:** canonical name/address/phone, categories, service area, map-pack competitors, reviews, citations, local landing pages and measurement.
- **Implementation:** map the approved pages and fixes to CMS changes, publishing, indexing, internal links and reporting.

## Rules for a pitch diagram

- Compress the delivery flow into five visible stages: protect, map, build, launch, learn. Omit learn when ongoing growth is outside scope.
- Use one main node per stage and connect it left to right. Add a branch only when the client has a real choice or a second outcome.
- Start with the client's current site and baseline, not with an SEO tool logo.
- Put live search intent and existing performance inside the map stage. They inform the architecture before pages are built.
- Put plugins, badges, schema types, privacy rules, speed targets and widgets inside the relevant node note. They are implementation details, not separate stages.
- Mark missing access, business choices and unsupported claims as `to confirm` nodes.
- Never present keyword volume, difficulty, traffic estimates or AI visibility as guaranteed demand or results.
- For local work, show Google Business Profile and review operations as their own branch. They are not an on-page footnote.

## Evidence order

Use the live public site for current public commitments. An explicit owner correction can supersede it when the owner says the site is stale. Search Console and analytics outrank third-party traffic estimates. Preserve any conflict instead of averaging it away.
